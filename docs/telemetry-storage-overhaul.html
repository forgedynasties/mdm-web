The database was growing forever. Now it finds a steady state on its own.

It started as four questions from a senior dev about queueing and storage. Measuring the answers turned up a table that had grown to 25 million rows with retention never switched on, sensor jitter writing a row every nine seconds, and a reconnect bug multiplying the request rate. This is what was measured, what shipped, and what is deliberately still open.

Keep the history, drop the resolution

Retention deletes a period outright. What a fleet actually wants from old history is its shape — when a device was powered, charging, on a pad — which survives at a fraction of the rows.

Why 10 minutes was the right rehearsal number and 5 is the right default: the daily rollup weights each sample by the gap to the next one, capped at 600 s. At or under that cap, online_minutes for a thinned day still recomputes correctly.

Store telemetry by what it is

A check-in row carries everything the device sent, so a wireless-charging flip costs a whole snapshot. Two tables split that by shape:

TableBytes/rowWritten when
checkins snapshot today665every stored report
device_samples — the numbers, in fixed columns~57every stored report
device_state_events — one row per real change~68only when something actually changes

Three test reports produced three samples and five events: wifi and ip on first sight, charging and pad status on the flip, ip again when it moved. Nothing at all while a state held.

The constraint that shaped the schema. The first cut stored tenths of a degree and whole percent — smaller, and it would have made the CSV export and the graph quote different numbers for one reading (34.400001525878906 against 34.4; 55.3% against 55%). The columns now hold the reading itself, and RAM stays as used and total so a percentage is computed the same way everywhere. Verified across 443,886 real rows: zero disagreements, on every field and on the derived percentage.

Reports, and two bugs the merge exposed

  • Weekly venue report — printable page, real PDF download, emailed through the existing SES mailer with recipients restricted to the company domain.
  • Ignore DPC check-ins — a switch for the agent's write volume while it learns to diff.
  • The WebSocket path had no OTA capability gate. HTTP refuses to hand the OTA command to a build that cannot apply it; over WS the same device got it anyway.
  • The WebSocket path never asked for an app list, so a re-flashed device kept showing its old apps indefinitely.

Both had been quietly true for as long as the two ingest paths were maintained by hand. Merging them into one function is what surfaced them — the refactor was worth more than the 37 lines it saved.

The one-line version. Check-ins are 42% fewer rows and a third smaller each, the table has stopped growing without a single day of history being deleted, and there is a verified restore point behind all of it. The structural half — storing telemetry by shape instead of as snapshots — is built, proven byte-identical on real data, and waiting on the remaining readers before it can pay off.
