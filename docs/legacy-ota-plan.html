Bring the legacy OTA server into the MDM.

Older builds ship com.aioapp.otautil, which polls a small FastAPI server for a system update at an address baked into the build. That address is the MDM dev box. The plan: the MDM speaks that app's protocol itself and takes over port 8000 on that host, so no device changes, and the FastAPI container retires. Progress for these devices comes from a per-device download URL and an update_engine logcat watcher, since the app never reports back.

Design the MDM becomes the OTA server

1 · Adapter routes on :8000MDM serves /device/poll, /device/check-update, /device/update-status in the legacy shape, published on the host's port 8000 (compose maps 8000 to the MDM container; only the /device/* paths answer there). Unauthenticated like today, rate limited per IP and serial, answers only for serials it knows or a pending deployment.
2 · Same deploy modelA push from Deploy creates the usual updates and update_devices rows. check-update resolves the device's pending row and returns the package. Incrementals only when the reported build matches the source build, same rule as TryCreateOTACommand.
3 · Per-device download URLupdate_url becomes an MDM link with a per-device token that streams the S3 object. The server counts bytes as they leave, so download progress is exact with no shell access.
4 · Install watcherOnce a device reports downloading, the MDM opens a logcat stream filtered to update_engine through the kiosk agent, parses progress and status lines, and feeds the same per-phase progress card the new agent uses.

How a legacy device shows up in the fleet

A serial that only ever hits /device/poll is a device without the MDM agent. The adapter upserts it with enrollment legacy, product from the serial prefix, capability set ota only, and last_seen from the poll. The device card gets a "Legacy OTA · pull" chip, and Deploy lists it with "polls every 15 min" instead of "online". If the same serial later enrolls the MDM agent, the record is the same row and the chip goes away. This also covers the "may run an HTTP check-in in firmware" case: anything that speaks the poll shape is accepted, nothing assumes a WebSocket.

Risks and limits

The address is not an Elastic IP

Stopping the instance loses 18.237.229.116 and orphans every hardcoded device. Options: never stop it (reboots are fine), or plan a firmware release that adds the S3 discovery lookup so a future move is possible.

Unauthenticated device routes

Same as today. Mitigation: serial format check, per-IP and per-serial limiter, answer only serials that exist or have a pending row, download tokens that expire with the deployment.

15 minute floor

The app ignores the 30 s in the config. A pull deploy starts within 15 minutes, not seconds. The UI must say so instead of showing stalled.

Reboot policy lives in the app

Force reboot and the window come from ota_config.json, not from the deployment's reboot setting. Either keep the S3 file the source of truth or send an agent reboot when the deployment says immediate and the device has an agent.

Private cache directory

The shell fallback for download progress needs the kiosk agent to read another app's cache. Likely denied on user builds; the per-device URL avoids the question.

Open questions

Which devices are actually on the legacy app in the field?

devices.json only shows bench serials from February. If production units poll it, the cutover needs a maintenance note; if not, it can happen any afternoon.

Do all field builds have the S3 discovery lookup?

The tree in ~/A15 does; the user reports older builds with only the hardcoded address. Until every build reads discovery, the host and port are fixed.

Should update_url move behind the MDM?

Yes for progress and for the LAN mirror item on the roadmap. It makes the MDM host a bandwidth path for multi-GB files; the dev box can do it, a CDN in front would be better for scale.

Keep the legacy admin dashboard?

Proposed: no. Groups, allowlists and packages all have MDM equivalents. The one thing it has that the MDM does not is the discovery file editor, which is the optional Settings item above.
