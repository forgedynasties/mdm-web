OTA discovery config

{{if .OTAConfigManaged}}managed by this server{{else}}not managed{{end}}
otautil reads ota_config.json from S3 on every poll and decides its own reboots from it: when an update finishes installing it reboots at once if the device's local hour is inside the window, otherwise it sets an alarm for the window's start hour. It has no "never reboot" setting. So the MDM publishes the file with the window always a few hours ahead of the reference clock and inside the small hours — a device that finishes an install defers, the MDM reboots it first, and the pending alarm dies with that reboot. Only one MDM should publish this file; every legacy device in the field reads it.

Request counters are in-memory and reset on restart; the learned index is persisted in the database.

persisted · avoids Google for known areas
