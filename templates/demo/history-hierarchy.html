Action history — three ways to cut the columns

The current table is 6 columns wide (Action · Target · Result · By · Sent · Actions) and every row pays for all of them even when most don't apply to a settled row. These three directions keep the same data but let one primary line carry the eye and push everything else into a quieter secondary line — fewer things fighting for attention per row.

Two lines per row instead of a 6-column grid: title + status badge on top, then target · result · by collapsed into one muted breadcrumb underneath. Sent-time and the action button move to the right edge, out of the reading line entirely.
Action history
Groups rows under day headers (Today / Yesterday / Aug 30…) so "sent" stops needing its own column — it's implied by the group. A thin timeline rail gives the list a scan-down rhythm; each row is a single line, meta trailing inline after the title.
Action history
Leans on the existing Needs attention / Completed buckets to carry hierarchy, then strips each row down further: a completed row shows only what happened (title + target + by, one line) — no result bar, no error line. A failed row adds its reason; nothing else changes shape.
