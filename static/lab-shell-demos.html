Lab view: a shell that feels like a shell

Today the console is an output box with a separate input and a Run button, so even when it is a live session it reads like "send a command, wait for a result". Two different things are mixed in it: a live session (one shell on the device, keystrokes and output streamed both ways, over its own channel on the device's socket, not the command queue) and one-off commands that go through the device's queue and come back as a result, which also work when the device is briefly offline or on an older client. These options separate the two.

X1 · A real terminal, with a queue beside it my pick

Two tabs. Terminal is a real terminal emulator (xterm.js): you click into it and type at the prompt, output streams in, Ctrl+C interrupts, ↑ recalls, colours and full-screen programs like top work. A status chip says connected and for how long; "End session" closes it. Queued commands is the other path: send a command through the device's queue and get its result back later, with a list of what was sent and each result — for when the device is offline, or a script you want recorded.

X2 · Prompt inside the output, no input box

Our own console, but the prompt and the cursor live in the output itself; you type where the output is. No Run button. Ctrl+C and ↑ handled by us. Queued commands stay as today's quick-command chips.

My recommendation

X1. A live session should look and behave like a terminal, and the queue is a different tool with different promises (works offline, recorded in Activity). Tabs keep each one simple and named for what it does.
