Settings → adb keys

The server now holds one adb key per vendor instead of one for everybody: a key baked into a vendor's image can only be replaced by a firmware release, so one shared key means a single leak reopens the whole fleet. The Settings card was built for exactly one key. Three ways it could show several — pick one and I'll build it.

The card keeps its shape; the single key block becomes a table. Upload gains a label box.

What I would pick: A.

The keys are one kind of thing and belong in one list; B's split invites two upload forms that do the same job, and C spends the most room on a fingerprint nobody reads twice. A keeps the fetch log, which is the part that matters when a key leaks — it is the only record of who took one. The "firmware" tag on the default row covers the one thing B is right about.
