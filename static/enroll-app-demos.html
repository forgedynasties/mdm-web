AIO Enroll — macOS app

A native Mac window that runs locally (no Tailscale, no SSH). Open the app → every device in the Mac's own adb devices appears → click Enroll → done. It watches for plug/unplug on its own, so there is no refresh button and no connect step. The server URL, adb binary and class tokens are bundled/fetched by the app, so the person never types anything.

Every option shows the same four states: Ready, Enrolling, Enrolled, Blocked (account present / other Device Owner) and Unauthorized (USB-debugging prompt not accepted).

Option A
Device list recommended
Plain list, one row per device, status chip and one action on the right. Closest to Finder / System Settings. Fastest to scan when a person plugs in 5–20 devices in a row. Class is a small dropdown next to the button, remembered from the last enroll.

Recommendation

A. It matches “open app, devices show up, click Enroll” with zero extra steps and handles one or many devices. Plug-and-play auto-refresh, per-row status, no connect button.

Decisions for you

1) Pick A / B / C (or mix). 2) Class tokens: today they are hardcoded in server.py. A distributed Mac app must not ship them or an admin key inside the binary — proposal: the app signs in once (admin key stored in macOS Keychain) and fetches/mints tokens from the MDM. 3) adb: bundle platform-tools inside the app so nothing needs installing. 4) Tech: proposal is Tauri/Swift-free-simple: a small Go or Swift app; I would choose Swift/SwiftUI for a real native window, or a Python+webview shell if you want to reuse the existing console logic faster.
