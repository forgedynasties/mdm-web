Renaming “Commands” — concepts

The page sends remote actions to devices: install/uninstall apps, screenshot, pull logs, run shell, reboot — and set a boot logo. “Commands” reads as a developer term, and a boot logo (branding, not an imperative) feels homeless in it. Two fixes, shown together: a clearer name, and a grouped builder so every action has an obvious home.

Step 1 · the name
Shortlist
Actions recommended
Plain English, covers everything you can do to a device — installing, rebooting, screenshotting, branding. Mirrors the device page’s “Controls”. Short enough for the nav.
Actions
Operations
More fleet-ops / enterprise tone. Good if you think of these as bulk operations across many devices. Slightly longer; “Ops” as a short form.
Operations
Manage
Verb-first, friendly. Reads well with the object (“Manage devices”). A touch generic, can blur with Settings.
Manage
Tasks
Honest about the model — actions queue and run on next check-in. But “tasks” can read as a to-do list rather than something you fire now.
Tasks
Step 2 · Option A

Step 2 · Option B
“Actions” with a category launcher
A bolder take: pick a category first (four cards), then the specific action as a chip. Scales better as you add actions and makes the branding/customization split obvious at a glance.

Selecting a category reveals its actions as chips and the matching config form below. “Customization” cleanly contains Boot logo (and anything branding-related you add later, e.g. wallpaper).
Alternative
Or: move Boot logo out entirely
If branding shouldn’t share a page with operational actions at all, Boot logo can move to a small Branding area (its own page, or a card under Settings / the device’s Controls). Then “Actions” stays purely operational. I lean against this — it’s an extra place to look — but it’s on the table.
Recommendation: rename to “Actions” + Option A (grouped rail). Lowest-risk, keeps everything one click away, and gives Boot logo an intuitive “Customization” home without a new page.
