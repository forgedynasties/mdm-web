Battery cycles under the graph

FW-2026-000054 asks for the charge cycle to show under the device graph, not only in About. Four placements below, same data in each: lifetime cycles (12.4), lifetime discharge (1243%), and — where an option uses it — cycles inside the window on screen (1.8), which is the number that actually changes as you move the range. The mock graph is static.

Option A
Chip in the footer row my pick

One chip on the right of the existing footer, beside the window label. The footer is already the graph's readout line, so nothing new appears on the page and the hover text keeps the whole left side.

Good at Zero extra height. Always visible, on every tab. Matches how the window label already sits there.
Bad at One number only — no room for lifetime discharge or per-window cycles. On a narrow window it competes with a long hover line.
Option B
Stat strip under the graph

A three-cell strip between the plot and the footer: lifetime cycles, lifetime discharge, and cycles used inside the window on screen. The third cell re-reads on every range change, so the strip answers "how hard was this device worked this week?".

Bad at ~46px of height on every device page, battery or not. The per-window figure needs a new server-side sum, so it is the biggest of the four to build.
