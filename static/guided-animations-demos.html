Guided motion across the MDM

The desktop Enroll app walks a person through a job with a few small, consistent moves: a numbered checklist whose current step glows accent and whose done steps turn green, a pulsing highlight on the thing to tap next with a ripple when it is tapped, toasts that slide in as things complete, and a bobbing help button on first run. The dashboard has none of this — a scout enrolment reads "step 3/8" in a static tag until you reload. Below: one vocabulary, five places it would apply, and what each move is for. All honour prefers-reduced-motion.

Recommendation

B as the one job-progress component, used everywhere a machine does steps — scout enrolment, installs, OTA, client updates — with the step names each job already has. C for the two or three setup sequences a human works through, lifted from the Enroll app as-is so the products match. D sparingly: one coach mark per page, shown once. E only as the companion that lets you walk away from the page. The moves themselves — pulse, draw-tick, slide-in, ripple — are the app's four keyframes, so one small shared stylesheet covers all of it.

Already shipped while this was being written: the scout card re-fetches itself every 3s during a job and the badge now reads "step 3/8 · Installing the agent" with a breathing dot — the minimum version of B's data path, so B can be built on top without another server change.
