Guided motion across the whole MDM

The desktop Enroll app guides with a handful of small, repeated moves: a numbered checklist whose current step glows and whose done steps turn green, a pulse on the thing to press next and a ripple when pressed, toasts that slide in, a spinner that is honest about waiting. The dashboard today has almost none of it: things change on reload, buttons give no feedback, long jobs are a number in a tag. Below, each page of the MDM: what it does now on the left, what it would do with the same five moves on the right. Everything honours prefers-reduced-motion.

The five moves one 60-line stylesheet, shared by every page

Recommendation

Adopt the five moves as one shared stylesheet (static/motion.css, ~60 lines, the app's keyframes renamed), then apply them in this order: 1 buttons that show their own in-flight/done/failed state (device page, clients, commands — the broadest payoff, no new data); 2 the step rail for every stepped job (scout enrol, install, OTA, agent update — one component, four step lists; the scout card already refetches itself so it is the first host); 3 arrive/glow on live lists (fleet, alerts, cmdk); 4 the checklist for first-run and new-restaurant; 5 one coach mark per page, shown once. Skip: anything that loops on a quiet screen — motion means something is happening, so a still page must be able to be still.
