A · Table + guided panel Recommended

The list becomes a real table — the same one Devices and Updates use — with columns for state, time left, reach and last change, and the groups as section rows. Live tunnels shrink to one strip of chips under the title (one chip per tunnel, ✕ to end), so the session is not written out twice. The panel is three fixed sections: Switch, Connect as numbered steps (open → allow → run → trust the key), History. The command is the biggest thing in the panel. Good: every fact has a column, nothing is a run-on caption; the steps tell a first-timer what to do next, including the refused-address case. Bad: a wider page; the table repeats the venue for every row.

B · Cards with a switch, drawer for connect

Each device is a card: serial, venue, an actual on/off switch, time left, a "tunnel" badge. Groups are card rows. Ticking cards raises a dark batch bar at the bottom. Click a card for a drawer with the connect steps. Good: the switch is the state — no "On" tag to read; batch stays out of the way until you tick; the drawer gives the connect steps their own stage. Bad: a per-card switch invites single clicks on a fleet page; drawer hides the list while you connect; less dense than a table, so 40 open devices is a long scroll.

C · Rail + inspector, like the device page

A narrow rail on the left (serial + a state pill, grouped), and a wide inspector on the right with a hero line and tabs: Connect (default), Switch, History. Big tiles answer the two questions first — is adb on, is a tunnel up — then the command. Batch is a "Select…" mode on the rail. Good: most room for the connect flow; mirrors the Clients page's rail so it feels native; the rail scales to hundreds. Bad: batch is a mode you enter rather than tick-and-go; venue and last change only show in the inspector, not in the rail.
