Access control audit, 30 Sep 2026

Started from a report that a user allowed to see one device could see the whole fleet. Every dashboard route that shows or changes devices was checked against the access policy (roles as ceilings, a per-user starting point, allow/deny rules scoped to all / restaurant / group / device). The fixes are live as of 4d91166f, d6aafde2 and 1bcd6bbc. On live today four accounts have a visibility limit: Talmiz Rehman (dev, one device), Ali Hassan (super op, Flights Vegas), Shahrukh Bashir (operator, one restaurant) and one restaurant owner.

The reported problem

Talmiz's access was set up correctly — start from nothing, allow See device on one device — but a separate switch, "Hide devices they can't see", was off. With it off the MDM listed every other device read-only, by design. Fixed: not being allowed to see a device now hides it everywhere, for every role, and the switch is gone. A device someone can see but not act on is still shown, read-only. A test that covered exactly this had been failing and CI was skipping it; it passes now and CI runs every test.
