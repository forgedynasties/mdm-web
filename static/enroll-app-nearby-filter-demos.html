AIO Enroll — telling our phones from the rest

The network never gives a phone's factory MAC (and Android hides it behind a random one anyway), but it does give the hardware serial — and our serials are structured. The MDM already knows the pattern through productions: product + model + variant + sku + batch + 5-digit sequence, with each batch owning a range of sequence numbers. So for every nearby phone the app can ask the server one question and get one of four answers:

✓ In your fleet the MDM already has this serial
AIO · T7 batch BU not seen yet, but inside a production batch's range
Looks like ours? our product and model code, but no batch covers it (new batch not entered, or a typo)
Other phone not our hardware

Three ways to use that in the Nearby phones list, all with the serial shown on every row. Each column shows the same five phones.

Option A · sort + chips + “Only ours” switch

Option B · Ours / Others tabs

Option C · ours up front, “3 others” folded

Option A
Ours first, each row labelled, one “Only ours” switch recommended
Our phones float to the top, each with a coloured chip saying why it is ours. Other phones stay in the list but dimmed and last. The switch in the header hides them (off by default, so an off-the-shelf phone you want to enrol is never lost).

Good: nothing is hidden by surprise, the reason is visible, one control. Bad: the list still contains the others unless you flip the switch.

Option B
Two tabs: Ours · Others
The group opens on Ours (2); Others (3) is one click away. Clean separation, nothing dimmed.

Good: very tidy. Bad: a phone that is mis-detected is hiding in the wrong tab.

Option C
Show ours, fold the rest behind “3 other phones”
Only ours are listed. Underneath, a quiet link “Show 3 other phones” expands them in place.

Good: least visual noise. Bad: the others are easy to overlook.

How it is decided (all options)

• The app asks the server in one call for all the serials on screen; the server looks up the MDM's devices and its production ranges (the same data as the Productions page).
• Nothing changes for how pairing works — this only labels and orders the list.
• A phone that is Looks like ours? gets a hint to add its batch on the Productions page — that is how a new batch is spotted early.
• Works the same for the pairing requests in the rail.
• Needs the small server addition (already written and tested: POST /api/v1/app/classify); it goes live only when you say so.

Pick A, B or C.
