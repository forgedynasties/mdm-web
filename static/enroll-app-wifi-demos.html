AIO Enroll — wireless adb: pair, connect, and when connect fails

Android 11+ can connect over Wi-Fi, but it takes two different address/port pairs (one to pair with a 6-digit code, another to connect), and both change often. That is why connect doesn't always work. These demos show how the app walks someone through it, finds the phone automatically when it can, and — when connect fails — retries on its own, then explains the likely cause in plain words with a one-click “Reset adb and try again”.

Press ▶ Play on each. The segment switches between a working run and a connect fails run.

Option A
“Wi-Fi” tab in the Help drawer recommended
Fits what you chose before (the “?” drawer). A fourth tab, Wi-Fi, walks four steps beside the animated phone: same network → turn on Wireless debugging → Pair (phone shows a code + pairing address; the app has two fields) → Connect (phone auto-discovered via mDNS, one click; manual IP:port fallback). The phone then appears in the normal device list.

Good: USB stays the default; wireless help is there when wanted, keeps the main screen clean. Bad: a bit hidden for someone who only has Wi-Fi to work with.

Option B
“+ Add over Wi-Fi” button in the device rail
A dashed button under the device list opens the same four steps as a full panel (no drawer). Once connected, the new device slides into the rail. More visible, aimed at benches that work wirelessly all day. Saved pairings: the app lists phones you paired before so “Connect” is one click next time.

Good: discoverable, great for wireless-first users, remembers paired phones. Bad: a permanent button in the rail that USB users never need.

What makes “connect” more reliable (both options)

1) Auto-discovery (adb mdns services): the app lists phones with Wireless debugging on, with the current connect port filled in, so nobody types a stale port.
2) Disconnect first, then 3 attempts a second apart (the first often fails right after pairing or wake-up); on the last attempt it restarts the adb helper.
3) Plain-language diagnosis on failure: different Wi-Fi / VPN, port changed (re-read it on the phone, it changes each time Wireless debugging is toggled), phone asleep, not paired yet, or a firewall blocking mDNS. Each with the fix.
4) Pairing mistakes caught early: the code is 6 digits, the pairing port is not the connect port, and the code dies when the dialog closes.
5) Bundled Google adb is used (some distro-built adb versions lack mDNS and show “Type the address instead”).

Pick A or B (I'd go A, with B's “saved phones” list inside it). After that I build it into the app.
