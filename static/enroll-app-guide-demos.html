AIO Enroll — guiding a new user, and fixing “no adb”

Three ways to hold a first-timer's hand, all with the same pretty animated phone illustration that shows exactly what to tap on the phone (tap Build number 7×, switch on USB debugging, press Allow). Each also shows the “adb not found” help, which detects your OS (Mac / Linux / Windows — this page detected ) and shows only the commands for it, with copy buttons and a Retry that re-checks instantly.

Normally the app bundles its own adb, so this card should be rare — it appears if antivirus removed it, the app was moved, or the bundled one cannot run. A “Use my own adb…” option picks a file by hand.

Option A
Checklist + live phone illustration recommended
The empty “plug in a device” screen becomes a 3-step checklist next to an animated phone. Steps tick themselves green as things are detected (adb found → device seen → debugging allowed). When adb is missing, an amber card sits above with OS-specific commands. Disappears for good once a device shows up.

Good: guidance lives exactly where the person is looking, goes away by itself, no extra screens. Bad: the tips are only visible while the list is empty.

Option B
First-run setup wizard
A friendly 4-screen welcome the very first time: Hello → we check your computer (adb scan animation; fails into the OS guide) → prepare the phone (animated phone) → plug in. Skippable, and reopenable from a menu. Most hand-holding.

Good: impossible to get lost; sets expectations. Bad: interrupts experienced users on first launch (mitigated by “Skip”), another screen to maintain.

Option C
Quiet main screen + “?” help drawer with smart nudges
Main screen stays clean (radar). A “?” opens a side drawer with tabs — Phone (animated steps), Computer (OS-specific adb help) and Trouble?. The “?” bobs and a tip appears if nothing is seen for 10 s (“Try another cable — some only charge”). adb-missing opens the drawer on the Computer tab automatically.

Good: never nags experienced users; answers live one click away; covers troubleshooting too. Bad: a new user must notice the “?” (hence the nudge).

Recommendation

A for the main flow, plus C's “Trouble?” drawer for rarely-needed help. A teaches by default without blocking anyone; the drawer holds the long tail (cables, drivers, udev rules) so the main screen stays pretty.

Per-OS facts both use: macOS needs nothing extra (Homebrew or the bundled adb). Linux may need your user in the plugdev group / udev rules, then log out and in. Windows needs the phone maker's USB driver on some brands (Samsung, Xiaomi, Huawei); Google/Pixel work with the generic one.
