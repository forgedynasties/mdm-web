Device wall — differentiate device class

From the Overview page's Fleet wall: every square today only encodes status (online/alert/offline/dormant) via color. For "AIO Test Bistro" the 5 squares are indistinguishable by type — a T7 and a KDS both just render as a colored square. The data is already there (db.WallDevice.Class is queried but never piped into wallSquare) — this is a real, small fix once a direction is picked.

Option B — shape per class Recommended
Status stays color, class becomes shape
Square = battery-powered class (T7, mpos, tablet), circle = mains-powered (kiosk, KDS, POS, dongle, payment). Two shapes read cleanly even at the 7px "sm" size used past 900 devices, and the status color language is completely untouched — no new legend needed beyond one line. Doesn't distinguish every one of the 8 classes, but answers the actual complaint (can't tell the KDS from the kiosk from the T7) well enough for a glance, and the tooltip still gives the exact class on hover.

Option C — class ring, status fill
A thin colored outline per class, fill stays status
Every one of the 8 classes gets its own ring color, independent of the status fill — most information-dense option. Risk: at 7px ("sm" density, 900+ devices) a 1.5px inset ring on an already-tiny square is hard to see, and 8 ring colors plus 4 status fills is two color systems stacked, more to learn than Option B's two shapes.

Option D — grouped by class
Sub-rows per class, instead of one flat grid
Clearest separation, but changes the block's shape (height grows with class count instead of wrapping as one grid), and "every square is a device" stops being a single flat scan — more structure than this widget's current "glance and move on" job calls for. Best reserved for a restaurant's own device page, not the fleet-wide wall.
