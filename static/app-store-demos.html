The app store page — three layouts, built on the real fleet

Option B's core claim is that the App library should answer where is this app, and where is it wrong. Every number on this page is a real query against the live fleet (device_packages joined to the 187 live devices), not a mock — because the layout question turns out to be secondary to what the data actually looks like.

What the live data says
The inventory is solid.

186 of 187 live devices report a full app list (>20 packages); one reports a thin list; none has never reported. So coverage is a reporting problem we do not have — the foundation is there.

"Nugget" is five apps, not one.

aio.app.nugget.uatv2 108 devices · .stagev2 26 · .internal 15 · aio.app.nugget 12 · .qa 7. That is 168 installs of the same product under five package names across a 187-device fleet. No current page shows this, and it is the single most useful thing the store would surface on day one.

Half the installs report no version.

50 of the 108 uatv2 installs have an empty version_name; all 7 aio.app.mpos.uatv2 installs do; 10 of 15 .internal. The store must render that as unknown and never fold it into "up to date" — a coverage bar that counts unknowns as fine is the dashboard lying again, which is the whole thing we just spent two days fixing.

Version strings are not comparable.

Observed on uatv2: 117-uatv2 (19 devices), 46.0.0-uatv2 (13), 47.0.0-uatv2 (12), 0.0.0-uatv2 (11), 39.0.0-uatv2 (2), 44.0.0-uatv2 (1). Two different schemes plus a 0.0.0 placeholder, so "newer than" cannot be computed. The reference has to be the version the app library declares, and everything else is "matches / does not match / unknown".

The library itself is ambiguous.

aio.app.nugget.internal has two library rows (51.0.0-internal and 400-internal), and the stagev2 devices run 19.0.0-stagev2 while the library declares 18.0.0-stagev2 — devices are ahead. So "Update" must never be offered blind: with no comparable ordering it would be a downgrade.

The table outlives devices.

206 device_ids appear in device_packages against 187 live devices, so rows survive hiding/retiring. Every coverage query must join the live device set or the denominators are wrong.

Note what is deliberately not offered: a plain "all devices". With 50 unknown versions on this package, "everything" would re-push an APK to devices that may already have it and cannot be checked — so the unknowns are excluded from the update target and named in the dialog rather than quietly included.

Deployed today: /apps is a flat library list with no fleet numbers at all. I would ship layout 2 with layout 3's findings panel above it, read-only first. Layout 1 is the prettiest and the least true to this fleet: five Nugget cards side by side hide the thing that matters. And slice 1 is worth doing even if you later reject the rest of Option B — the six findings at the top of this page came out of one query, and nobody can currently see any of them.
