Clients page — the firmware client as one row

GMS is not supported any more, and no label should name a tree (QCOM is the default and the only line built). But 101 of the 188 live devices run v2.0.x images — 54% of the fleet — and agentSlotFor maps them to the firmware-gms slot. The decision is what their rows say, now that there is one Firmware MDM row and no build published for their platform key. Slot keys, the publish API and ?slot= links do not change in any option.

Recommendation

B. It gets the count right (188 = the fleet), names no tree, and the one thing it adds — a row state that says "no build for this image" with a disabled Update and a tooltip — is the honest answer to the only question those 101 rows raise. C reuses existing vocabulary but states something false next to a version number that is plainly there. D is B plus a collapse, and is worth doing later if the 101 rows turn out to drown the list; it is a presentation tweak on top of the same data, not a different decision.

Either way the plumbing is the same: one display slot for the firmware client, with the device's real slot still deciding what may be installed — which is what stops a v2.0.x device ever being offered a build its platform key rejects.
