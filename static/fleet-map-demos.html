Fleet map: filters, blips and the device popup

Three things on Fleet → Map view: the map ignoring the left rail, several devices at one place drawing on top of each other, and a popup that is Google's white box. Every mock below uses the real tokens, so light and dark are accurate. Pick one from each of parts 2, 3 and 4.

1 · Filter bug2 · Blips3 · Popup4 · Map chrome
1 · The filter bug is already fixed (not deployed, not committed). The map reloads the moment the list swaps, but the page address only changes after that swap, and the map reads the restaurant, group and release from the address. So it always showed your previous click. The list now tells the map once the address has changed (fleet:scoped in templates/devices.html). Please check it on stage: click three different restaurants in a row with the map open, and the blips should match the third one.

2 · Several devices in one place

Today every device is its own dot, so a restaurant with four tablets shows four dots on top of each other, and the grey cluster number only appears when you zoom out. The idea is to group by place (same spot within about 30 m), so one restaurant is always one blip with a count, at every zoom.

Recommendation

2A · 3A · 4A. The site blip (2A) fixes the stacking problem and also adds what the grey cluster never had: health at a glance. The adaptive card (3A) is the same component for one tablet or four, themed for dark mode. The chips (4A) are the cheapest way to make the filter fix visible. Spiderfy (2C) can come later on top of 2A if you want individual dots at the highest zoom. Nothing here changes the roster, only the map, and the server side is one small change: /devices/map.json would also return a site key (the restaurant, or the coordinate rounded to ~30 m) so the page can group.
