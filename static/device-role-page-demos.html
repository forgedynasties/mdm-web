Device page: a deployed device, and the same device in debug

A deployed device has one job. Its page should say is it doing that job: online, role app running, on prod, locked. Lab tools (install any APK, free shell, slot picker, arbitrary OTA) appear only when a device is flagged for debug, which you decided can happen at a venue too. Debug expires by itself, default 24 hours, and the device then goes back to prod and lock. Names are placeholders. See the plan.

1 · One page, debug as a timed mode

Same URL for both. Debug adds a banner with the countdown, a Debug tab and the lab actions. Turning it off, or the timer running out, removes them. Try the switch.

Good: one page, one URL, so a support link always works. The deployed view is short and answers "is it working". Debug is loud, visible and temporary, which covers the risk of a restaurant device left off prod.
Bad: the page changes shape, so people need to notice the banner. The four-tile strip needs per-role variants, for example no battery on a KDS.

My recommendation

Option 1. You chose debug at a venue with an expiry, and only a mode on the device itself can carry that. It keeps one URL, keeps the deployed page short for the people you are rolling out to next, and makes the risky state impossible to miss. Option 3 suits only the lab teams, who are not the long-term audience.
