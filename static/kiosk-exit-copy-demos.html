How staff get out of kiosk: saying what is true

The kiosk rule editor asks "How staff get out" and offers an "Offline exit code" switch that says the code changes every minute. In fact every device accepts one fixed exit PIN, compiled into the client, whatever the switch says; it also accepts the rotating code on its device page. The switch reaches no device. You chose to keep the fixed PIN and make the page honest, so the switch goes. The options below differ in how much the page says. The rules list loses its "· exit code on" note for the same reason.

3How staff get out

The same on every device; nothing to set here.

  1. Press Power five times within 10 seconds. A keypad opens over the app.
  2. Enter the exit PIN, or the code shown on the device's page in the MDM. Both work with no connection.
  3. Kiosk comes back on the next restart, or when the rule is saved again.
Good at
  • Answers the question it asks, in the order a technician does it.
  • Nothing left to toggle that does nothing.
Bad at
  • Takes the same space as before for something that isn't a choice.

B · Question 3 goes; a footnote under the editor

The editor asks two questions (where, which app) and a name. One line under Save says how staff get out.

Name

Staff leave kiosk on the device with five Power presses and the exit PIN (or the code on the device's page). Kiosk comes back on the next restart.

Good at
  • The editor only asks things you decide.
Bad at
  • Easy to miss; "how do staff get out?" is the first thing a restaurant asks.

Recommendation

A. "How staff get out" is a question people ask, so answer it where they look, as three steps, without a switch. Leave the PIN itself off the page (C) and keep pointing at the device's page for the rotating code, which is the one worth handing out. The stored per-rule setting stays in the database unused, so nothing is lost if the choice changes later.
