Map labels: restaurant name and device count

Today a restaurant is a bare coloured dot on the new Overview's map, and you have to click it to see which one it is. Below are five ways to label it with its name and how many devices it has. Each option is drawn twice: left is a fleet like live today (two restaurants), right is a busy one (31 restaurants in one county), where labels start to collide. The map underneath is a stand-in drawing; on the real page it is the Google map. The names are made up.

Current: dot only Deployed

Size is device count and colour is state. The name and count only appear in a popup after a click.

A · Name pill beside the dot

A white pill next to the dot reads "Pho 88 · 20". The count turns red when the restaurant is at risk. When pills overlap, a label moves to the other side of its dot, and if there is still no room it is hidden until you hover.

Good at
  • The easiest to read: the name is at normal size on a solid background.
  • Looks like Google's own place labels, so it fits the map.
Bad at
  • Takes the most room. In a busy area about a third of the labels have to hide.
Build
  • An HTML overlay on the Google map (an OverlayView). No new Google setup needed.

B · Count in the dot, name underneath Recommended

The device count is printed inside the dot, and the name sits under it in small text with a halo, the way Google labels a town. The count never hides. Only a name gives way when two collide, and restaurants at risk get their name drawn first.

Good at
  • The count is always visible, even in the busiest area, because it lives inside the dot.
  • Takes the least room of the options that show both, so the fewest names hide.
Bad at
  • Small text on a map background is harder to read than a pill, especially over busy streets.
Build
  • The count inside the dot is Google's built-in marker label, so it needs no custom code. The name underneath is a small overlay.

C · Callout card

A small card above each restaurant shows its name, "18 of 20 online" and a bar with the offline share in red. This is the most information without clicking.

Good at
  • The best fit for a fleet like today's: with two or three restaurants, each one gets a proper status card.
Bad at
  • Doesn't scale. In a busy area the cards cover the map, so most have to hide.
Build
  • An HTML overlay, the same as A.

D · Status chip: name, online, offline

A chip with the name, a green online count and a red offline count, e.g. "Pho 88 ●14 ●6". The offline count only appears when there is one.

Good at
  • Answers "how many are down there" without a click, which a total count doesn't.
Bad at
  • Two numbers per label is busier, and the dot's colour already says there's a problem.
Build
  • An HTML overlay, the same as A.

E · Count only, names when it matters

Every dot shows its count, but only restaurants at risk or on watch show their name. Healthy ones show theirs on hover. The map stays clean and the trouble spots are named.

Good at
  • The cleanest busy map, and the names you see are the ones you need.
Bad at
  • On a good day with no problems you see numbers and no names. That doesn't meet "labelled with the name" all the time.
Build
  • The same as B.

Recommendation: B

B, the count in the dot with the name underneath. It's the only option that shows both on every restaurant today and still works when the map fills up: the count can't be hidden, and when names collide the healthy ones give way to the ones at risk. C is nicer with two restaurants but falls apart at thirty. A is easier to read but hides the most labels. If you like the pill style, B with A's pill for the name is a reasonable mix.
