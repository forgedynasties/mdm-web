Long lists: Clients, Enrollment, Wireless adb

Today these pages print every row. Clients (per-group rows, Releases), Enrollment (Recent enrollments, Inbox), Wireless adb (Open / Off / Can't groups) have no cap and no pager. Fleet is ~290 devices, so a group can run to a couple of hundred rows. Three ways to cap them; the same mock (the adb page's "Open now" group) stands in for all of them.

A · "Show all N" button Today on the device pageI'd pick this

First 25 rows render, the rest are in the page but hidden; one button under the list shows them. Same control the device page already uses for actions (.app-more). Good: zero server change, tick-all and client-side filters still see every row, one click to see everything, nothing to re-learn. Bad: a 300-row page still ships 300 rows (fine at this fleet size).
