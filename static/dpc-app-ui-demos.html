DPC agent status screen (ui/MainActivity) — layout options

The on-device screen shown on an enrolled DPC device itself (not the dashboard). Read-only — no server URL/key to type, enrollment arrives by QR or the adb extras used today. Already does a lot right: battery row is only added if (battery() != null) (correctly hidden on mains-only hardware at the UI layer, matching the mains-power fix we just scoped), and columns already go two-wide above 720dp and stack below it. Mocked here against the 3 devices onboarded today: rbox (TV, D-pad only, wide), D3 Pro / KDS (touch, narrower panel).

Option 1 — current two-column cards
As shipped (0.2.3+) deployed today Recommended — keep
Hero card (device + status + check-in/settings) up top, then Management + Device in column 1, Policies + Capabilities + Privacy in column 2. Columns side-by-side ≥720dp (rbox), stacked below it (Sunmi touch panels, and the one Samsung mpos phone in the fleet). Good: every field has a label, nothing is guessed, capability chips make degraded caps (no root → shell/screen_capture/input/logcat) visually distinct without a paragraph of caveats. Already handles the no-battery case correctly by omitting the row rather than showing 0%.

Option 2 — tabbed sections
Status / Device / Policies tabs
One section visible at a time, same content, no responsive column logic needed at all. Shrinks scroll length on small touch panels. Costs an extra tap (or D-pad move) to reach anything past the first tab — worse for the rbox, which is glanced at via remote and wants everything visible without navigating. Only worth it if a much smaller screen joins the fleet (a handheld mpos, which the catalog already has as a class).

Option 3 — compact single list
No cards, section labels only
Flattest, cheapest to render, smallest code surface. Loses the capability chips' at-a-glance color coding (degraded caps become just another row of text) and the visual separation between "this is critical" (hero) and "this is detail" — a glance from across a kitchen at the KDS would have to read text instead of spotting a red/green dot. Not recommended for any of today's 3 devices, but noted since it's the cheapest option if a very constrained display (e-ink, segment LCD style KDS) ever needs this screen.
