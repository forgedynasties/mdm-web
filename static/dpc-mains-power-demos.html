DPC devices with no battery — stop showing one

Found testing today's 3 onboarded devices (HK1 RBOX D8 · dongle, Sunmi D3 Pro · pos, Sunmi D2s KDS · kds) — all mains-powered, all showing a battery figure on the dashboard anyway (0%, 50%, 50%). Two independent bugs, not one:

Client (aio-mdm-client-dpc, net/Telemetry.kt:52) — the no-battery guard exists (// A TV box / dongle has no battery… send no battery fields at all) but trusts BatteryManager.EXTRA_PRESENT, defaulting to true when the extra is absent. These boards' battery HAL reports present=true with a synthetic level regardless, so the guard never fires. (ui/MainActivity.kt:401, the on-device status screen, defaults the opposite way — false — so the phone/TV screen and the dashboard can already disagree about the same device today.)

Server (internal/product/product.go, CapsForDevice) — only device_class == "dongle" gets Caps{} (no battery). pos and kds fall through to genericCaps (HasBattery: true) because their product keys aren't in the static catalog — so even a dashboard that honours CapsForDevice would still show a battery on the Sunmi units.
