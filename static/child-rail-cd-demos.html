D vs C — hover each mock's left edge

Both are at real sizes (56px collapsed app rail, 196px child rail) and both react to hover like the dashboard does. Put the pointer anywhere in a mock to open its app rail. D is what is on stage right now; C is here so the two can be compared on the same screen.

D · The app rail floats over it on stage now

The child rail never changes: full labels, counts, the current row. The app rail grows over the top as a drawer, with a shadow and a scrim, and is gone when you leave. Nothing is abbreviated, because nothing is squeezed.

C · Squeeze to a colour swatch per entry

The reciprocal swap is kept, but the 56px strip is swatches rather than letters — each row's colour is derived from its name, so it is stable, and the current row gets an accent ring. Good: two venues are told apart, which icons cannot do, and nothing has to be abbreviated. Bad: the colour is arbitrary until you have learned it; the same rail at rest shows the swatch beside the name, so there is a chance to learn it. Watch the strip lose its headings — "Restaurants" and "Groups" have nowhere to go.
